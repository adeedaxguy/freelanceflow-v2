# QA findings remediation - 11 September 2026

Follow-up to [the full QA report](qa-2026-09-11.md), based on commit 85d99d4.

## Implemented

- Removed company-name-to-domain guessing from 19 job adapters. Missing company websites stay empty, application URLs remain available, and jobs can be saved without a domain. Known job-board domains no longer receive the company-website quality bonus.
- Sanitized legacy guessed domains at saved-lead read/save boundaries and in the version-9 search cache migration. Existing records, search parameters, local results, notes, and manual leads are not deleted. Where a legacy job domain exactly matches the old guess, the code conservatively hides it; that can hide a coincidentally correct domain because historical provenance was not stored.
- Greenhouse now requests full content, decodes HTML, and carries longer descriptions into proposals. Explicit hybrid/on-site jobs are excluded without rejecting technical phrases such as hybrid cloud or jobs offering a remote option.
- RemoteOK uses an identifiable client header, JSON acceptance, a bounded 15-second timeout, and feed-shape validation. A direct request from the development machine returned HTTP 200 / 100 entries. Production availability still requires the post-deployment check.
- Proposal generation now has validated output, Groq/OpenAI fallback, bounded requests, redacted failure audit events, and an admin-only rate-limited connection diagnostic. Editable template fallback is labelled clearly and no longer asserts invented experience or availability. The actual provider configuration is not assumed healthy until the live diagnostic passes.
- Replaced fabricated status/uptime/incident data with a truthful team-maintained status view. Status notices published through Admin > Email campaigns also appear on this page after explicit publication confirmation. This is not automated monitoring.
- Replaced inert status/changelog forms with separate topic subscriptions, rate limits, email confirmation, one-use expiring confirmation tokens stored as hashes, and topic-specific signed unsubscribe links. GET links do not change subscriptions, protecting against email link scanners.
- Confirmed newsletter subscribers are available as separate admin audiences. Existing account marketing-consent and plan filters, campaign confirmation, duplicate protection, and batch limits remain. No existing user is opted in automatically.
- Templates and follow-ups now handle failed loads/saves/deletes, timeouts, retry, and in-flight mutation locking. Built-in templates remain alongside custom ones. Follow-up editing is explicit rather than on-blur, and failed saves preserve the draft. Gmail preparation is not reported as email delivery.

## Verification

- 395 tests across 77 suites passed. Nine opt-in provider tests in two suites were not rerun.
- Type check passed. Production build passed, with existing image warnings and the known local blog fallback because DATABASE_URL is absent.
- Twelve isolated production-build browser checks passed at 1440x1000 and 390x844: status, changelog, templates, follow-ups, admin email campaigns, and admin settings.
- Browser checks used an isolated in-memory database fixture and intercepted API responses. They verify rendering, errors, draft preservation, and responsive layout, not actual email delivery or provider connectivity.
- No page-level JavaScript errors or horizontal page overflow were detected in these checks. Static UI type/layout detector reported no findings.
- Regression tests cover original-source descriptions, remote/hybrid distinctions, unknown website saving, cache preservation, provider errors, newsletter confirmation/unsubscribe/topic isolation, admin access and consent, and failure-state recovery.
- Raw screenshots and local results are in ignored reports/qa-findings-* files. Post-deployment checks must distinguish real live results from these fixtures.

## Deployment And Boundaries

No dependency additions, destructive data migration, paid-plan changes, Stripe mode changes, Twilio changes, calls, live charges, or customer campaigns are part of this change. The unrelated blog work is excluded.

NewsletterSubscription is an additive PostgreSQL table initialized on first use, consistent with the existing rate-limit/audit storage pattern. It does not modify User consent or billing data. The public status notice uses the existing PlatformSetting table. A rollback leaves these additive records intact.

Real inbox delivery is awaiting permission for a single owner-address test. Production AI/source diagnostics are the next release verification step. The broader QA report's untested real payment fulfillment, telephone audio, and normal-user entitlement scenarios are not certified by this remediation.
